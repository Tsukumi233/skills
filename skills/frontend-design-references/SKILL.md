# 前端设计参考工作流（Vibe Coding）

整理自埃弗里特鱼《存 25 个 Vibe Coding 的参考网站》。

核心观点：**garbage in, garbage out**。“干净一点”“高级但不要太高级”这种词给 AI 留的发挥空间太大。与其再加十个形容词，不如拿一张参考图，指出喜欢的是哪种排版、哪段交互，或者直接给组件代码。

## 什么时候用

- 用户想做网页、落地页、个人主页、产品官网、工具站，或者某一个区块（导航、页脚、定价、hero）
- 需求里出现模糊审美词：高级、极简、有设计感、酷炫、干净、有质感、不要太普通
- 用户想要某种动效或交互，但说不清叫什么（“鼠标跟着走的那种”“数字滚动”“卡片发光”）
- 页面整体风格已经差不多，但某一块显得挤、收尾仓促或太普通

## 工作流程

### 1. 先把模糊词拆开

遇到审美形容词时，先别急着写代码，判断缺的是哪一层：

- **整体叙事**：第一屏讲什么，中间靠什么让人往下读，最后怎么收
- **视觉关系**：字和图各占多少，留白在哪，字重、边距、图片怎么裁
- **局部组件**：导航、页脚、卡片、按钮
- **交互/动效**：hover、滚动视差、鼠标反馈、状态切换

然后：要么请用户给参考（截图、链接、组件代码），要么根据下面的速查表推荐 2–3 个具体参考方向让用户挑。一次只问一个问题。

### 2. 看缺的是哪类参考

| 缺什么 | 去哪一类 |
|---|---|
| 整页风格、叙事顺序 | Ⅰ 整站类 |
| 只有某个区块不行 | Ⅱ 局部类（缩小范围比换掉整套风格更有效） |
| 效果知道了，要能直接落地的代码 | Ⅲ 实现类 |
| 想故意跳出常规、找新的输入 | Ⅳ 风格集合站 |

### 3. 写一份“参考说明”，不要只丢一个链接

一个参考站里通常只有一部分是用户真正喜欢的。必须写清楚**只参考什么**，这样省 token，参考也准。模板：

```
参考：<站点/案例名 + 链接或截图>
只借鉴：<整体风格 / 滚动视差 / hover 效果 / 信息呈现顺序 / 标题排法 / 色彩反差 / 产品展示方式 …>
要保留的比例：<图文比例、留白、字号层级、图片裁切>
不要借鉴：<配色 / 背景 / 某个动效 …>
展开状态/其他尺寸：<导航展开图、手机端截图（如有）>
技术栈：<React / Vue / 纯 CSS>，依赖：<如 motion-v、Tailwind、Three.js>
```

### 4. 实现阶段：拿代码，别猜截图

- 有可调参数的组件站（React Bits、OriginKit、Animata 等），先调到接近目标，再把**参数 + 源码 + 依赖 + 放在哪个位置**一起作为输入。
- **框架要对口**：Vue 项目用 Vue Bits，不要把 React 代码塞进 .vue 文件。
- 有网络访问时，直接读组件文档页、安装命令和源码；没有时请用户把代码或链接贴过来。
- 动效要去真实页面体验，静态截图看不出动画。

### 5. 收尾：统一

从不同来源借来的零件，最后都要统一字体、间距、颜色、圆角和动效节奏，让它们看起来像同一个产品。

## 原则

1. **用参考替代形容词**：一张图加一句“喜欢它的 X”，胜过十个形容词。
2. **跨行业迁移**：做 A 行业的网站，不必只看 A 行业。食品、建筑、作品集里的好处理都能搬过来，AI 擅长迁移。
3. **先定内容结构，再定视觉处理**：别把三个网站最好看的部分直接拼在一起，单看都好，合起来大概率会乱。
4. **极简≠删内容**：说“极简”时要说明哪些比例和内容要保留，否则 AI 可能把内容一起精简掉。值得学的是取舍。
5. **先定主角再加效果**：每块卡片都发光，主次就没了。小效果点到为止（比如统计数字用 Number Ticker，好过整页铺粒子）。
6. **单页先做好**：小工具、活动页、个人主页，先把一页讲清楚（介绍、功能、信任感、行动按钮），别急着拆出很多分支页。
7. **高频操作的工具，交互反馈比开场动画重要**：折叠、切换、弹窗、开关的小反馈更值得打磨。
8. **学会分类名词**：Typographic、Grid Layout、Unusual Layout、Unusual Navigation、Mega Menu、Brutalism 这类词能让以后的描述更专业、更准。
9. **页脚和导航也是设计**：别做成最后随手塞一个 logo 加几列链接。

## 参考站速查

> 链接打不开时按站名搜索。部分站点有付费/Pro 内容。

### 00 标杆
- **Awwwards**（awwwards.com）：网页创意与交互的审美标杆。

### Ⅰ 整站类：看完整叙事和整体风格

| 站点 | 适合 | 怎么用 |
|---|---|---|
| Lapa Ninja（lapa.ninja） | 看整页内容顺序 | 有整页截图和视频；顺着看首屏→中段→结尾的叙事；可按分类/颜色/字体筛 |
| CSS Design Awards（cssdesignawards.com） | 拆解“凭哪个细节让人记住” | UI/UX/创新分项评分；动效要点进实站体验 |
| One Page Love（onepagelove.com） | 小工具、活动页、个人主页 | 学怎么在一页里讲清产品 |
| Websitevice（websitevice.com） | 按行业找（咖啡店、牙科、酒店、教育、咨询…） | 站内对布局特征的简短描述可以直接复制给 AI |
| Siteinspire（siteinspire.com） | 图文占比、留白、字体风格 | 用 Typographic / Grid Layout / Unusual Layout 分类找，顺便学名词；告诉 AI 连同图片比例和留白一起参考 |
| Minimal Gallery（minimal.gallery） | 少元素里的精细取舍 | 极简不等于小字，常有大字体；要说明哪些比例要保留 |
| Land-book（land-book.com） | 同类页面横向比较 | 有 Sections（hero/功能/定价/评价）拆开收录，卡在某一段时直接找区块 |
| Godly（godly.website） | 桌面/手机对照、局部设计 | 详情页分开列桌面、手机和区块，适合研究响应式；收藏靠直觉，交给 AI 时要翻译成具体点 |
| Httpster（httpster.net） | 跳出千篇一律的 SaaS 风 | Unusual Layout / Unusual Navigation 分类；老案例也值得看 |
| Saaspo（saaspo.com） | 真要解释功能的产品 | Landing/Pricing/Product/Customers 分开看，可按行业/风格/技术栈筛；重点借鉴信息顺序，而不是背景 |
| Curated（curated.design） | 顺着标签找相似案例 | 先找到喜欢的，再看它怎么被归类，慢慢积累描述词 |

### Ⅱ 局部类：只修某一块

| 站点 | 适合 | 注意 |
|---|---|---|
| Navbar Gallery（navbar.gallery） | 静态导航、下拉、侧栏、全屏菜单、Mega Menu | 必须提供**展开后**的状态，否则 AI 不知道里面长什么样；工具站和内容站尤其值得参考 |
| Footer Design（footer.design） | 把页脚做成最后一处亮点 | 可按字体、网格、明暗、风格筛，有手机画面 |

### Ⅲ 实现类：直接拿 demo、参数和源码

| 站点 | 技术栈 | 擅长 | 注意 |
|---|---|---|---|
| Codrops（tympanus.net/codrops） | 多样（含 Three.js/WebGPU） | 难以描述的交互，有教程+demo+源码 | 把教程、仓库和要改的部分一起给；检查 WebGPU 等兼容性 |
| React Bits（reactbits.dev） | React | 文字动画、背景、鼠标反馈 | 可调参数，带 Code 和 Copy for AI |
| Vue Bits（vue-bits.dev） | Vue | React Bits 的 Vue 移植版 | 部分组件依赖 motion-v，记得一起带上 |
| OriginKit | 代码 / Framer / MCP | 可视化调参的效果（如 Cursor Ring Field） | 有免费和付费内容，逐个看获取要求 |
| Magic UI（magicui.design） | React | Number Ticker、跑马灯、边框、文字动效 | 只取需要的；给出文档、安装方式、目标值和位置 |
| Aceternity UI（ui.aceternity.com） | React/Next.js + Tailwind + Motion | 光线、背景、发光边框（Glowing Effect） | 先定主角再挑效果 |
| Animate UI（animate-ui.com） | React，分 Radix UI / Base UI 等分支 | 折叠、标签切换、弹窗、开关的状态动效 | 按项目底层方案选对分支 |
| Cult UI（cult-ui.com） | shadcn 体系 | 信息怎么放：ShiftCard 的 hover 双层、浮动面板、方向感知标签 | 先借交互结构，再统一视觉 |
| Uiverse（uiverse.io） | HTML/CSS（也有框架版本） | 按钮、开关、输入框、加载状态 | 作者多、风格杂，最后要统一视觉 |
| Animata（animata.design） | React | 把“动起来”拆成参数（如 Typing Text 的间隔、循环、光标） | 有安装命令和手动复制代码 |
| Hover.css（ianlunn.github.io/Hover） | 纯 CSS | hover 效果词典：位移、下划线、背景、阴影 | 个人/开源与商业授权不同，直接用库代码前先看条款 |

### Ⅳ 风格集合站
- **Brutalist Websites**（brutalistwebsites.com）：粗野主义，默认蓝链接、大字、铺满全屏。只借一个排版或一组颜色就够了。
- 也可以翻大品牌的历年官网（比如 Shopify 历季网站的 3D 视差创意），或者顺着喜欢的案例挖同风格的集合站。

## 反模式

- 只说“做得高级一点”“酷炫一点”，不给任何参考
- 丢一个获奖网站让 AI“照着做”，却不说喜欢它哪一点
- 只给收起状态的导航截图，或者只给静态截图来描述动画
- 拼接多个站点各自最好看的部分，导致整体失调
- 一个页面里装下所有逛到的好东西
- React 组件直接贴进 Vue 项目，或者漏掉依赖（motion-v、Tailwind、Motion、Three.js）
- 忽略付费/授权条款就直接用库代码

## 结语

审美不是标准答案，而是在大量输入里慢慢形成的取舍判断。帮用户的时候，目标是让他们能说清自己喜欢什么，而不是把收藏夹塞满。
